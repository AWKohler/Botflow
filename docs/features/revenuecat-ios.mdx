---
title: RevenueCat for iOS
description: Add subscriptions and in-app purchases to a Botflow Swift app, test them in the simulator, and get ready for the App Store.
---

Botflow uses [RevenueCat](https://www.revenuecat.com) for subscriptions and in-app purchases in Swift apps. You connect your own RevenueCat account by pasting one key. Botflow sets up the rest, and you can make test purchases in the simulator straight away: no Apple Developer account, no App Store Connect, no real money.

<Note>
In-app purchases are available on the **Pro and Max** plans, for Swift projects that have a backend. The setup lives in the **Payments** tab of the workspace.
</Note>

## Ask for what you want to sell

Tell the agent what the app sells, in plain words:

```
Add a Pro subscription for $4.99 a month that unlocks unlimited habits.
Show a paywall when a free user reaches the limit.
```

The agent builds the paywall and the purchase flow, and opens the **Payments** tab for you. It keeps building while you connect RevenueCat, then creates the products as soon as you have.

## Connect RevenueCat

<Steps>
  <Step title="Create a RevenueCat project for this app">
    Sign in to the [RevenueCat dashboard](https://app.revenuecat.com) (free to start), open the project menu at the top left and choose **Create new project** (platform: **Native Apple**). Use one RevenueCat project per app, so each app has its own products.
  </Step>
  <Step title="Create a secret key">
    In that project, open **API keys** in the left sidebar and choose **New secret API key**. Set:

    - **API version** to **V2**
    - **Project configuration permissions** to **Read & write**

    Leave the other permissions at **No access**, choose **Generate**, and copy the key with the copy button beside it. It starts with `sk_`.

    <Warning>
    RevenueCat does nothing when you choose **Generate** with every permission left at **No access**. Set **Project configuration permissions** first.
    </Warning>
  </Step>
  <Step title="Paste the key into Botflow">
    In the **Payments** tab, paste the key and choose **Connect**.
  </Step>
</Steps>

That key is the only value Botflow needs. From it, Botflow:

- finds your RevenueCat project
- reads the Test Store key for simulator builds, and the App Store key once you add an App Store app
- adds a webhook to your RevenueCat project, so purchases reach your app's backend
- stores the key encrypted; it is never sent to your app or to the agent

## What the agent sets up

Once RevenueCat is connected, the agent creates what your app sells in RevenueCat:

| RevenueCat term | What it is | Example |
| --- | --- | --- |
| Product | One thing a user can buy | `pro_monthly`, $4.99 a month |
| Entitlement | The access a purchase unlocks | `pro` |
| Offering | The set of products a paywall shows | `default` |
| Package | A product's slot in an offering | Monthly |

The **Payments** tab lists the products with their test prices and what each unlocks. It also names anything that would stop a purchase from working, such as a product that is on no paywall or unlocks nothing.

<Note>
When you create a RevenueCat project, RevenueCat offers to add starter products (Monthly, Yearly and Lifetime) at prices it suggests. If you accepted them, the agent replaces or removes them so the paywall sells exactly what you asked for. The unused starter products stay in RevenueCat, listed in the Payments tab as "not for sale in the app".
</Note>

<Tip>
A Test Store price cannot be changed after the product is created. To try another price, ask the agent for it: it creates a new product and swaps it into the paywall.
</Tip>

## Try a purchase in the simulator

1. Open **Preview** and start the simulator.
2. Open the paywall in your app and tap a purchase button.
3. In RevenueCat's **Test Store Purchase** dialog, choose **Test valid purchase**. Nothing is charged.

The app unlocks at once, and the purchase appears under **Activity** in the Payments tab within a few seconds, with a note that it reached your backend.

Test subscriptions run on a fast clock: a monthly subscription renews about every five minutes and ends by itself after about half an hour. That lets you see renewal and expiry without waiting a month.

## Test mode and live mode

There is no switch to remember. Botflow puts the right key in each build:

| Build | Purchases |
| --- | --- |
| Simulator preview and development builds | Simulated through RevenueCat's Test Store |
| App Store builds | Your real products, real money |

A test build can never charge anyone. An App Store build never contains the Test Store key. Until RevenueCat is connected and the App Store steps below are done, a build would have purchases switched off, so **Publish** stops and asks before uploading one.

## Sell for real on the App Store

Test mode needs none of this. Before your first App Store release, with a paid Apple Developer account:

<Steps>
  <Step title="Add your App Store app to RevenueCat">
    In RevenueCat, open **Apps**, add an **App Store** app with your app's bundle ID, and add the in-app purchase key it asks for.
  </Step>
  <Step title="Create the products in App Store Connect">
    Create each product with the same ID it has in the Payments tab (for example `pro_monthly`) and set its real price.
  </Step>
  <Step title="Let Botflow pick it up">
    In the **Payments** tab choose **Check again**, then ask the agent to register the products for the App Store.
  </Step>
</Steps>

Apple reviews in-app purchases together with the app, so real purchases start working once the release is approved.

## Troubleshooting

| What you see | What to do |
| --- | --- |
| Nothing happens when you choose **Generate** in RevenueCat | Every permission is still **No access**. Set **Project configuration permissions** to **Read & write**, then generate. |
| "That is a V1 (legacy) secret key" | Create a new key with **API version** set to **V2**. |
| "That key is missing a permission" | In RevenueCat, open **API keys**, choose **Edit** in the key's **···** menu, set **Project configuration permissions** to **Read & write**, then connect again. |
| "That is an SDK key (public)" | You pasted a `test_` or `appl_` key. Botflow needs the secret key, which starts with `sk_`. |
| "RevenueCat does not recognise that secret key" | The key was deleted, or part of it was cut off when copying. Create a new one. |
| "The RevenueCat project … is already connected to …" | A RevenueCat project can be connected to one Botflow app, because it holds one app's products, paywall and purchase events. Create a new RevenueCat project for this app, or disconnect the other app first. If the other connection is one you can no longer reach, revoke its key in RevenueCat (**API keys**) and connect again. |
| Test purchases: "no Test Store" | In RevenueCat, open **Apps**, add a **Test Store**, then choose **Check again** in the Payments tab. |
| The paywall is empty | Open the Payments tab. "What your app sells" names what is missing; **Ask the agent to finish** fixes it. |
| A purchase succeeds but the backend never hears about it | Under **Setup**, "Your app's backend" shows whether the receiver is deployed. **Ask the agent to finish** deploys it. |

## Disconnecting

**Disconnect RevenueCat from this project**, at the bottom of the Payments tab, deletes the stored key and the webhook Botflow added. Your RevenueCat project, products and customers stay as they are. Deleting the project in Botflow does the same.

If Botflow cannot remove its webhook when you disconnect (for example, because you revoked the key first), the Payments tab tells you so and links to **Integrations** in RevenueCat, where you can delete the webhook named "Botflow: …".
